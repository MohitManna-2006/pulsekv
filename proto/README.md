# `proto/` — the frozen v2 cross-language contract

Three services bind the polyglot pieces of PulseKV v2 together:

| File | Service | Server lives in | Called by |
|---|---|---|---|
| `node.proto` | `NodeService` | `node/grpc_shim/` (C++ shim over the C engine) | the Go control plane |
| `metadata.proto` | `ClusterMetadataService` | `control/` (Go) | clients, adapters, operators |
| `adapter.proto` | `AdapterService` | nothing yet — Phase 7 | Python LLM adapters |

This contract was frozen in Phase 0 precisely so Phases 1 (C data plane) and 2
(Go control plane) can proceed independently. Adding fields is fine. Renaming
or removing an RPC is a breaking change to work already written against it.

## Generating code

One script drives everything:

```sh
deploy/gen-proto.sh          # Go + Python
deploy/gen-proto.sh --all    # Go + Python + a standalone C++ generation check
```

C++ for the shim itself is generated by CMake at build time (see below), so the
plain invocation deliberately skips it; `--all` runs a throwaway C++ generation
into a temp directory purely to prove all three files compile under `protoc`'s
C++ backend.

## Checked in vs. generated at build time

The three languages get different treatment on purpose:

| Target | Output | Checked in? | Why |
|---|---|---|---|
| Go | `control/gen/**` | **yes** | `cd control && go build ./...` then needs nothing but a Go toolchain. This is the dominant Go convention (grpc-go, etcd, and friends all ship generated `.pb.go`). |
| Python | `adapters/pulsekv_adapters/gen/**` | **yes** | `pip install ./adapters` then works without `protoc` or `grpcio-tools` on the machine. |
| C++ | `node/grpc_shim/gen/**` | **no** — gitignored | Generated `.pb.cc` is tied to the exact `libprotobuf`/`libgrpc++` ABI it will link against. Checking it in would break the moment the image's Debian packages move. CMake regenerates it on every configure. |

Regenerate Go and Python inside the v2 dev image so the pinned plugin versions
are what actually produced the checked-in files:

```sh
docker run --rm -v "$PWD:/src" -w /src pulsekv-v2-dev deploy/gen-proto.sh
```

Exact pinned versions live in `deploy/Dockerfile` and are restated in
`docs/pulsekv-v2-phase0-summary.md`.

## One post-processing step, and why

`grpc_tools.protoc` emits `import node_pb2 as node__pb2` in the generated
`*_pb2_grpc.py` — a top-level absolute import that breaks as soon as the
generated modules live inside a package. `deploy/gen-proto.sh` rewrites those to
`from . import node_pb2 as node__pb2`. This is the standard workaround for
protobuf's long-standing Python packaging gap
(<https://github.com/protocolbuffers/protobuf/issues/1491>); it is applied by
the generator script, never by hand.
